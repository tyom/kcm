Keep your .env files. Move the secrets to the macOS Keychain.

kcm import lets you choose which values in .env.local to store in your Mac's Keychain. It replaces those values with keychain:// references. Your teammates can keep using plain values in their own .env.local.

Then start your app with kcm use -- npm run dev. It sees DATABASE_URL and API_KEY as normal environment variables.

kcm is for development secrets on your own Mac. Install kcm or see how teammates can work without it.

What it is

  • kcm is one Bash script. It uses the security tool that ships with macOS and needs no service or account. It runs on Bash 3.2 or later.
  • It reads the env files you already have. kcm use merges .env, .env.<mode>, .env.local and .env.<mode>.local from the current folder up to the git root, where <mode> is $NODE_ENV. A variable already set in your shell wins, as with dotenv.
  • Your teammates don't have to use it. A small wrapper script runs a command through kcm when kcm is installed, and as it is when it isn't. Someone without kcm, or without a Mac, keeps real values in a gitignored .env.local.
  • What a file scan sees In a supply chain attack, a compromised dependency may scan your .env files for secrets. After kcm import, that scan finds keychain:// references for the values you selected. kcm is not for CI runners, production credentials, shared Macs or highly sensitive data. Read the security notes before you rely on it.

Use cases

Move the secrets you already have

kcm import lists every plain value in your env files with a masked preview and ticks the ones that look like secrets. 

kcm import                  # scan env files from here up to the git root
kcm import -e .env.local    # or a single file

Tick the values you want to import and press Enter to review them. kcm asks for confirmation before it stores anything or edits a file. It reads each stored value back before replacing its line with a reference.

The first row shows OPENAI_API_KEY in ./.env.local with the masked value sk-p…9f2c. kcm ticks it because the name contains KEY and the value starts with sk-. Scroll the example sideways to read the other rows' notes. 

       NAME                    FILE          VALUE      NOTES
> [x]  OPENAI_API_KEY          ./.env.local  sk-p…9f2c  name has KEY, starts with sk-
  [x]  STRIPE_KEY              ./.env.local  sk_l…a1b2  name has KEY, starts with sk_live_ · in Keychain, same value
  [x]  GITHUB_TOKEN            ./.env.local  ghp_…0123  name has TOKEN, starts with ghp_ · in Keychain, different value
  [ ]  EXPO_PUBLIC_SENTRY_DSN  ./.env.local  http…6848  name has DSN, looks random · public, so unticked
  [ ]  PORT                    ./.env        ****
  ✓    DATABASE_URL            ./.env.local             keychain://DATABASE_URL
  !    REDIS_URL               ./.env.local             keychain://REDIS_URL missing from Keychain
↑/↓ move  space toggle  a all  enter continue  q quit
  • [x] A plain value selected for import.
  • [x] Green: your Keychain already has this name with the same value. kcm only replaces the line with a reference.
  • [x] Yellow: your Keychain already has this name with a different value. kcm asks what to do after you press Enter.
  • ! Yellow with !: the line is already a reference, but its Keychain entry is missing. You can't tick it.
  • ✓ Dimmed: the line is already a reference and its Keychain entry exists. Nothing to do.

kcm keeps no backup of the file, because a backup would hold the plain values. Quitting at any prompt changes nothing.

Rotate any secret you import from a file that git tracks. The old value stays in git history.

Share scripts with people who don't use kcm

Add a small wrapper to the repo.

kcm install-wrapper

kcm asks where to put it. The default is scripts/with-env.

Commit the wrapper and call it from your scripts, for example in package.json. 

"scripts": {
  "dev": "scripts/with-env vite"
}

Everyone runs npm run dev. If kcm is installed, the wrapper uses it to start Vite. Otherwise it starts Vite directly, and Vite reads .env.local.

Keep keychain:// references out of committed env files. Each person puts them in a gitignored .env.local, and people without kcm put real values there.

Without kcm the wrapper loads no env files. Next.js also reads .env.local itself. Node with dotenv and Docker Compose read only .env by default, so point them at .env.local. A plain shell script has to load the values itself.

Start a new project

Add each secret once. kcm asks for the value.

kcm add DATABASE_URL
kcm add STRIPE_KEY

After each one it prints the line to put in your .env.local file. 

DATABASE_URL="keychain://DATABASE_URL"

Then run any command with the references filled in. kcm finds and merges .env files from the current folder up to the git root. 

kcm use -- npm run dev

Give one script its own credentials

Store a second set of credentials under different names, then point the names the script reads at them in a separate env file. 

kcm add STAGING_AWS_ACCESS_KEY_ID
kcm add STAGING_AWS_SECRET_ACCESS_KEY

Make sure git ignores .env.staging, then add these two entries to that file. 

AWS_ACCESS_KEY_ID="keychain://STAGING_AWS_ACCESS_KEY_ID"
AWS_SECRET_ACCESS_KEY="keychain://STAGING_AWS_SECRET_ACCESS_KEY"

--env-file loads only that file. --override uses its values even if your shell already exports AWS credentials. 

kcm use --override --env-file .env.staging -- ./deploy.sh

Install

With Homebrew

Use kcm for development secrets on your own Mac.

brew install tyom/tap/kcm

By hand

Download the script from the main branch.

curl -O https://raw.githubusercontent.com/tyom/kcm/main/kcm

Read the script with less kcm. When you're ready, install it.

chmod +x kcm
sudo mv kcm /usr/local/bin/

The first run

The first time kcm reads a secret, macOS asks for your password or Touch ID. Choose "Always Allow" to stop it asking again for that secret.

Stop using kcm

kcm export -e .env.local -o .env.local.plain writes the real values to a new file. Then mv .env.local.plain .env.local puts them back in the file your app reads. Comments in the file are not kept.

Check your app still works. Then kcm remove NAME deletes the Keychain entry for NAME. The README covers every command.
